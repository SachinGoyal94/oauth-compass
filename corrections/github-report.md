# GitHub OAuth App Guide — Verification Report (agent-verified, human-supervised)

Verified against official GitHub documentation only (docs.github.com). Date: 2026-11-03.
Draft: `knowledge/guides/drafts/github/v1.md` · Corrections: `corrections/github.json`

## Confirmed

- Registration navigation (profile photo → Settings → Developer settings → OAuth apps) and button wording "New OAuth App" / "Register a new application" for first-time users — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
- Required fields: Application name, Homepage URL, Authorization callback URL; optional: Application description; optional "Enable Device Flow" checkbox (exact wording confirmed) — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
- Up to 10 callback URLs per OAuth app ("You can enter up to 10 callback URLs.") — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
- Up to 100 OAuth apps per user or organization ("A user or organization can own up to 100 OAuth apps.") — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
- "Expire user access tokens" is enabled by default at registration — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
- App can be registered under a personal account or any organization you have administrative access to (resolves a draft "unverified" item) — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
- OAuth apps have no GitHub-run app review; no OAuth docs page mentions any review process. `approval_wait: None` is correct — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps
- OAuth apps act as the authenticated user; scopes never grant permission beyond what the user has — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps
- Authorization endpoint `GET https://github.com/login/oauth/authorize` with client_id, redirect_uri, scope, state (state "strongly recommended", unguessable, CSRF protection) — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
- PKCE is supported and strongly recommended; `code_challenge_method` must be S256, plain is not supported — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
- Authorization code expires after 10 minutes — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
- Token endpoint `POST https://github.com/login/oauth/access_token`; refresh via refresh_token grant; refresh rotates (old access + refresh tokens stop working); scope cannot be changed on refresh — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
- "The access token expires after eight hours, and the refresh token expires after six months without use." — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps and https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/best-practices-for-creating-an-oauth-app
- `offline_access` is a documented scope: yields an expiring access token + refresh token even if the app is not configured for expiring tokens — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps and https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps
- ~35 scopes documented; users may grant fewer than requested; overlapping scopes normalized (user + user:email → user) — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps
- 2,000 access token requests per hour for OAuth apps; 10 sign-ins in an hour forces re-authorization on the next sign-in; secondary rate limits apply — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/rate-limits-for-oauth-apps
- Token creation limit: ten tokens issued per user/application/scope combination, ten tokens created per hour — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
- OAuth app API calls use the user's rate limit of 5,000 requests per hour — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps and https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api
- x-ratelimit-* response headers are the authoritative rate limit status — https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api
- Wildcard matching for callback URLs only when necessary (security risk); device flow phishing risk; prefer authorization code with PKCE — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/best-practices-for-creating-an-oauth-app
- SAML SSO: token has no access to an org whose SAML SSO the user has not completed; check `GET /user/installations` regularly (confirms the draft's endpoint, though its source page was wrong) — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/best-practices-for-creating-an-oauth-app
- GitHub Apps preferred: fine-grained permissions, repo-level install, installation tokens expire ~1 hour, rate limits scale; OAuth apps cannot use granular permissions — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps
- Store client secret and tokens securely (key vault / encrypted env vars; refresh tokens stored separately); avoid sensitive data such as internal URLs in app info — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/best-practices-for-creating-an-oauth-app and https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
- Every registered OAuth app gets a unique Client ID and Client Secret; never leak the secret — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authenticating-to-the-rest-api-with-an-oauth-app

## Corrected

1. **"6m refresh" (summary/gotcha) → 6 months.** The draft's shorthand "6m" reads as minutes; the refresh token "expires after six months without use" (and access token after 8 hours). Also added rotation behavior (old access + refresh token stop working after refresh) — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
2. **Removed undocumented "Callback URLs must be HTTPS (localhost allowed for dev)" (step 4 nuance, prerequisite 3).** No official page states a blanket HTTPS requirement. What the docs do say: redirect_uri must exactly match a registered callback URL unless wildcard matching is enabled, and loopback callbacks may use a different port (`http://127.0.0.1/path` registered, `http://127.0.0.1:1234/path` used) — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
3. **Reframed "Unchecking 'Expire user access tokens' creates long-lived tokens (legacy) but is discouraged".** Docs frame unchecking as for apps whose "authentication code hasn't been updated to support short-lived tokens" (no "discouraged" language); also added that offline_access yields expiring tokens per-authorization even when the app-level setting is off — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app and https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
4. **Fixed step 7 source attribution.** The 2,000/hour token limit and 10 sign-ins/hour limit are on the rate-limits page (not the authorizing page); SAML SSO + `GET /user/installations` guidance is on the best-practices page (not the authorizing page) — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/rate-limits-for-oauth-apps and https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/best-practices-for-creating-an-oauth-app
5. **Fixed gotcha #2 source.** The 8h/6-month token lifetimes are not stated on the creating-an-OAuth-app page; they are on the authorizing and best-practices pages — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps
6. **Removed over-attributed source claim.** The draft's sources list said the "Building OAuth apps" overview supports "No review/approval process, immediate usability" — that page says no such thing. The no-review fact is an absence across all OAuth docs, not a documented statement; sources list corrected accordingly — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps
7. **Downgraded "client secret shown only once" (step 5).** Not stated anywhere in official docs (UI behavior only); action/nuance reworded and moved to the could-not-verify list. The verified part (unique Client ID + Client Secret issued at registration; store securely) now cites the authenticating page — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authenticating-to-the-rest-api-with-an-oauth-app
8. **Removed "Accept GitHub Terms of Service if prompted" (agent_vs_human).** No doc support for any ToS acceptance step in registration — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
9. **Resolved two draft "unverified" items as confirmed:** (a) "Enable Device Flow" checkbox wording is documented; (b) org-level creation requires administrative access to the organization, no extra permission documented — https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
10. **Added missing verified facts:** REST API rate limit of 5,000 requests/hour (the user's limit, shared across apps acting for that user) with x-ratelimit-* headers; the ten-tokens-per-user/application/scope-combination limit; and that organizations can require owner approval of OAuth app installs via an org application policy (softens the "usable immediately" verdict; there is still no GitHub-run review) — https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api, https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps, https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps

Note: the REST rate-limits page has moved; `https://docs.github.com/en/rest/overview/rate-limits` returns 404. Working URL: https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api
