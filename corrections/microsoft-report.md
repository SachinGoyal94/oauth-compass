# Human-verification report — Microsoft Identity Platform OAuth guide (draft v1)

Verified against official Microsoft documentation only (learn.microsoft.com). Draft: `knowledge/guides/drafts/microsoft-identity-platform/v1.md`. Corrections: `corrections/microsoft.json`.

## Confirmed

Claims checked against official pages and found accurate:

- **Registration path and flow** — Entra admin center → Entra ID/Identity → App registrations → New registration; record Application (client) ID / Directory (tenant) ID from Overview; redirect URI is optional at registration (Graph docs even say leave it blank). [quickstart-register-app](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), [auth-register-app-v2](https://learn.microsoft.com/en-us/graph/auth-register-app-v2)
- **Supported account type options** — "Accounts in this organizational directory only" / "Accounts in any organizational directory" / "Accounts in any organizational directory and personal Microsoft accounts" / "Personal Microsoft accounts" all match official wording; multitenant + personal exists as described. [auth-register-app-v2](https://learn.microsoft.com/en-us/graph/auth-register-app-v2)
- **Redirect URI rules (nearly all)** — HTTPS required in production with `http` allowed only for localhost (port ignored for localhost matching); max 256 chars per URI; max 100 URIs when personal accounts are supported vs 256 for work/school-only; no special chars `! $ ' ( ) , ;`; no IDN; URIs live on the application object, never the service principal. [reply-url](https://learn.microsoft.com/en-us/entra/identity-platform/reply-url)
- **Client secret shown only once**; certificates are the recommended more-secure alternative. [howto-create-service-principal-portal](https://learn.microsoft.com/en-us/entra/identity-platform/howto-create-service-principal-portal), [auth-register-app-v2](https://learn.microsoft.com/en-us/graph/auth-register-app-v2)
- **Delegated vs Application permissions**; application permissions only admins can consent to. [permissions-consent-overview](https://learn.microsoft.com/en-us/entra/identity-platform/permissions-consent-overview)
- **User.Read needs no admin consent; User.Read.All / Group.Read.All / Directory.ReadWrite.All are admin-restricted** — non-admin organizational users are blocked with an "not authorized to consent" error. [scopes-oidc](https://learn.microsoft.com/en-us/entra/identity-platform/scopes-oidc)
- **Endpoints and tenant values** — `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/authorize` and `/token`; `{tenant}` = common / organizations / consumers / tenant ID; 'common' for multitenant + personal; `offline_access` required for refresh tokens. [v2-oauth2-auth-code-flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow), [v2-protocols-oidc](https://learn.microsoft.com/en-us/entra/identity-platform/v2-protocols-oidc)
- **PKCE** — required for SPAs, recommended for all clients; public clients must not use secrets or certificates when redeeming codes. [v2-oauth2-auth-code-flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)
- **Publisher verification requirements** — free and optional; verified MCPP Partner Global Account (location IDs unsupported), work/school registration only (MSA not supported — error MSANotSupported; B2C tenants not supported — B2CTenantNotAllowed; national clouds not supported), publisher domain set and not *.onmicrosoft.com, domain matching MCPP email-verification domain, dual roles (Application Administrator or Cloud Application Administrator + CPP Admin/Accounts Admin), MFA, Terms of Use acceptance. [publisher-verification-overview](https://learn.microsoft.com/en-us/entra/identity-platform/publisher-verification-overview), [troubleshoot-publisher-verification](https://learn.microsoft.com/en-us/entra/identity-platform/troubleshoot-publisher-verification)
- **Badge on consent prompts** — blue verified badge / "Unverified" shown in the consent prompt; unverified-publisher warning targets newly registered multitenant apps (permissions beyond basic profile, risk-based step-up consent enabled). [publisher-verification-overview](https://learn.microsoft.com/en-us/entra/identity-platform/publisher-verification-overview), [application-consent-experience](https://learn.microsoft.com/en-us/entra/identity-platform/application-consent-experience)
- **Token facts added during verification** — access token default lifetime variable 60–90 min (75 min average); refresh tokens default 90 days (24 hours for SPA redirect URIs) and rotate on every use, revoked on password change/admin/user revocation. [access-tokens](https://learn.microsoft.com/en-us/entra/identity-platform/access-tokens), [refresh-tokens](https://learn.microsoft.com/en-us/entra/identity-platform/refresh-tokens)

## Corrected

Fixes written to `corrections/microsoft.json` (only affected guide sub-objects included, each complete):

1. **Review timeline framing (summary, difficulty, time, step 7) — most important correction.** The draft presents "3–5 business days standard review, minutes fast-track" as the publisher-verification timeline. Official docs say the app verification itself processes "in a few minutes" and "Developers who have already met these requirements can be verified in minutes." The documented 3–5 business day window belongs to the **Partner Center/MCPP account verification** ([understand-the-verification-process](https://learn.microsoft.com/en-us/partner-center/enroll/understand-the-verification-process): "In most cases, the process takes three to five business days"), a prerequisite — not to this step. The draft's "24–72 hours for status propagation" is community-reported only (docs say replication "may take some time").
2. **Admin-consent roles (step 6).** Draft claimed "Admin consent requires Global Administrator or Privileged Role Administrator." Current docs ([grant-admin-consent](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/grant-admin-consent)) list: **Privileged Role Administrator** (any permission, any API incl. Microsoft Graph application permissions), and **Cloud Application Administrator, AI Administrator, or Application Administrator** (everything except Microsoft Graph application permissions); Global Administrator is not listed on the current page. Admin consent endpoint `/v2.0/adminconsent` (never 'common') added.
3. **Registration role requirement (prerequisites 1–2, step 1).** Draft required Application Administrator/Cloud Application Administrator "to create app registrations." The Entra quickstart requires only **Application Developer** at minimum (the Graph quickstart says Cloud Application Administrator for its steps); the elevated roles are required **only for publisher verification**. MCPP/Partner-Center-role/publisher-domain/MFA prerequisites upgraded from `reported` to `verified_from_docs`.
4. **Wildcard claim (step 4, gotcha 2).** Draft said flatly "Wildcards unsupported." Docs: wildcards are **unsupported for apps that sign in personal accounts**, but **allowed via manifest editor (strongly discouraged) for work/school-only apps**. Also added: no query parameters in redirect URIs when personal accounts are supported; IPv6 loopback [::1] unsupported; SPA platform must use `spa` redirect type.
5. **Client secret cap (step 5).** Added the documented 24-month maximum ("Client secret lifetime is limited to two years (24 months) or less") and Microsoft's recommendation of less than 12 months, plus federated credentials as a third credential option.
6. **Single-tenant badge claim (step 2, gotcha 3).** "Single-tenant apps do not show the verified publisher badge" is **not stated in current official docs**; docs say verification is "primarily" for multitenant apps. Reworded to the doc-backed statement; the absolute claim moved to unverified/reported.
7. **Blockers 1–2.** "MPN ID doesn't exist" and stuck-verification blockers upgraded from `reported` to `verified_from_docs` using the official error reference (MPNAccountNotFoundOrNoAccess, MPNGlobalAccountNotFound — use PartnerGlobal ID not PLA; B2CTenantNotAllowed; MSANotSupported; PublisherDomainMismatch; InteractionRequired with the in-session MFA rule). Non-official Q&A escalation link replaced with official docs.
8. **Sources.** Removed the non-existent `consent-and-permissions-overview` and `publish-app` slugs (404) and the `ka-ge` locale duplicate of mark-app-as-publisher-verified; sources list rebuilt (17 entries) from pages actually verified, official learn.microsoft.com pages first.
