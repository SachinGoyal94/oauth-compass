# Slack OAuth Guide v1 — Verification Report (agent-verified, human-supervised)

Verified against official Slack documentation only (docs.slack.dev is Slack's official developer docs domain; all api.slack.com URLs cited in the draft 302-redirect there). Date: 2026-11-03. Corrections applied in `slack.json`.

## Confirmed

- **OAuth V2 endpoints** are `https://slack.com/oauth/v2/authorize` and `https://slack.com/api/oauth.v2.access` — https://docs.slack.dev/authentication/installing-with-oauth
- **Authorization code expires after ten minutes** ("your temporary authorization code, which expires after ten minutes") — https://docs.slack.dev/authentication/installing-with-oauth
- **Redirect URI must match or be a subdirectory of a configured Redirect URL**, "The `redirect_uri` must use HTTPS", and "A Redirect URL can *not* contain an anchor (`#`)" — https://docs.slack.dev/authentication/installing-with-oauth
- **With multiple Redirect URLs, the same redirect_uri must be sent in both Authorize and Access steps** (otherwise `bad_redirect_uri`) — https://docs.slack.dev/authentication/installing-with-oauth
- **Bot tokens begin with `xoxb-`, user tokens with `xoxp-`** — https://docs.slack.dev/authentication/tokens and https://docs.slack.dev/reference/methods/oauth.v2.access
- **SIWS scope conflict**: "A scope conflict occurs when attempting to combine Sign in with Slack (SIWS) user scopes with non-Sign in with Slack scopes in the same OAuth flow… Each set of scopes must be requested in a separate OAuth flow" — https://docs.slack.dev/authentication/installing-with-oauth
- **SIWS scope names** openid ("View information about a user's identity"), email ("View a user's email address"), profile — https://docs.slack.dev/reference/scopes
- **Optional scopes**: users "can choose which ones to grant" during install; declared via `bot_optional`/`user_optional` manifest fields — https://docs.slack.dev/authentication/installing-with-oauth and https://docs.slack.dev/reference/app-manifest
- **State parameter**: "If it doesn't match what you sent, consider the authorization a forgery"; state verification is "strongly recommended" CSRF mitigation — https://docs.slack.dev/authentication/installing-with-oauth and https://docs.slack.dev/tools/node-slack-sdk/oauth/
- **Token rotation is optional**, enabled via `settings.token_rotation_enabled: true` or the OAuth & Permissions toggle; access tokens "will always expire in 43,200 seconds, which is 12 hours" with `xoxe.` prefix; refresh tokens are single-use; "Token rotation may not be turned off once it's turned on" — https://docs.slack.dev/authentication/using-token-rotation
- **No formal review for installing to your own development workspace** (undistributed apps live on one workspace) — https://docs.slack.dev/app-management/distribution and https://docs.slack.dev/tools/bolt-python/creating-an-app
- **Console creation flow**: sign-in required ("You'll need to sign in to your Slack account to create an application"); enter App Name, select development workspace, click Create — https://api.slack.com/apps and https://docs.slack.dev/app-management/quickstart-app-settings
- **Manifests are YAML or JSON** and can be used to create apps in the console — https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests
- **Scopes used as examples are real**: chat:write ("Send messages as your Slack app"), commands ("Add shortcuts and slash commands…"), channels:history ("View messages and other content in public channels…") — https://docs.slack.dev/reference/scopes
- **Marketplace requirements**: privacy policy, publicly accessible support page, "provide clear reasons for each of the scopes", advanced security review possible — https://docs.slack.dev/slack-marketplace/slack-marketplace-app-guidelines-and-requirements
- **Secure storage guidance** (never hardcode, secrets managers in production, don't distribute client secrets, limit redirect URIs to domains in your control) — https://docs.slack.dev/authentication/best-practices-for-security
- **Enterprise Grid**: org-wide install requires an Org Admin — "an Org Admin will receive a direct message from Slack to review the request"; admin installs to the org "then further decides which workspaces to add it to" — https://docs.slack.dev/enterprise/developing-for-enterprise-orgs
- **HTTPS-for-localhost gotcha stands**: the current OAuth V2 doc requires HTTPS with no localhost exception; only the *legacy* Sign-in-with-Slack doc allows plain-http localhost — https://docs.slack.dev/authentication/installing-with-oauth and https://docs.slack.dev/legacy/legacy-authentication/legacy-sign-in-with-slack

## Corrected

- **"Public distribution requires Marketplace review" — WRONG, conflated.** Unlisted public distribution via Manage Distribution → "Activate Public Distribution" gives a shareable install URL and "Add to Slack" button with **no Slack review** ("perfect for when you want to test out your app by running a pilot for early customers"). Slack review applies **only** to Slack Marketplace listing (directory presence) — https://docs.slack.dev/app-management/distribution. Fixed in summary, time.verdict, and by splitting the old step 10 into new step 10 (unlisted distribution, no review) and step 11 (Marketplace listing).
- **"Review timeline not published; reported several business days to weeks" — OUTDATED.** Official timelines exist: preliminary review "generally takes up to 10 business days"; functional review "up to 10 weeks for new submissions and 6 weeks for published apps resubmitting changes" — https://docs.slack.dev/slack-marketplace/slack-marketplace-review-guide. Fixed in time.approval_wait, step 11, and blockers.
- **Marketplace submission prerequisite missing**: apps under 10 installed active workspaces "will be blocked from submitting" (as of July 2026, maintained throughout review) — https://docs.slack.dev/slack-marketplace/slack-marketplace-review-guide and https://docs.slack.dev/changelog/2026/09/01/slack-marketplace-install-requirement. Added to step 11 and blockers.
- **Step 10 location wrong**: "Manage Distribution → Submit to App Directory" → submission happens from "the **Submit to the Slack Marketplace** section of your app's configuration page" — https://docs.slack.dev/slack-marketplace/slack-marketplace-review-guide. Fixed in step 11.
- **"From scratch" button label outdated**: current docs say select "**Blank app**" then Continue ("From a manifest" is the alternative) — https://docs.slack.dev/app-management/quickstart-app-settings. Fixed step 2.
- **"Install to Workspace" button label**: current docs say "**Install App to Workspace**" — https://docs.slack.dev/tools/bolt-python/creating-an-app. Fixed step 7.
- **Client secret "shown once" — UNSUPPORTED claim, removed.** No Slack page says the secret is shown once; Basic Information "contains… important credentials you'll need later" and the FAQ documents resetting it via the "Change secret" button — https://docs.slack.dev/tools/bolt-python/creating-an-app and https://docs.slack.dev/faq. Fixed step 4.
- **"Mark optional scopes by unchecking 'Required'" — invented UI detail.** No per-scope "Required" flag exists in the manifest schema; optional scopes are declared via `bot_optional`/`user_optional` (which "must also be listed in the corresponding bot/user fields") — https://docs.slack.dev/reference/app-manifest and https://docs.slack.dev/authentication/installing-with-oauth. Fixed step 6.
- **`token_management_enabled: true` — wrong field for enabling rotation.** The token-rotation doc says to set `token_rotation_enabled: true` under `settings` (or use the OAuth & Permissions toggle); the manifest reference's `oauth_config.token_management_enabled` is a different, org-deploy-related boolean — https://docs.slack.dev/authentication/using-token-rotation and https://docs.slack.dev/reference/app-manifest. Fixed step 8.
- **"Access tokens expire (typically 1-12 hours)" — imprecise.** With rotation they "will always expire in 43,200 seconds, which is 12 hours" — https://docs.slack.dev/authentication/using-token-rotation. Fixed the token-rotation gotcha.
- **"redirect_uri… must be sent in token exchange" nuance — wrong.** Official rule: if multiple Redirect URLs are configured, send it in both steps with identical values; if no redirect_uri is sent, "the OAuth flow will use the first Redirect URL listed on the App Management page"; in the token exchange it is required only "if your app passed it as a parameter to `oauth/authorization`" — https://docs.slack.dev/authentication/installing-with-oauth and https://docs.slack.dev/reference/methods/oauth.v2.access. Fixed step 5 and step 9.
- **Mis-citation**: the Node SDK OAuth guide (https://docs.slack.dev/tools/node-slack-sdk/oauth/) contains **no manifest example and no token_management_enabled** — the draft's step 8 evidence pointed there. Re-pointed to the app manifest reference; kept the SDK page for state-verification support only.
- **Missing gotcha added — scope changes require reinstall**: "adding scopes only take effect for existing installs after workspaces reinstall your app", and "It is not possible to downgrade an access token's scopes" (removal requires revoking the token) — https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests and https://docs.slack.dev/authentication/installing-with-oauth.
- **"Rate limits on OAuth endpoints not documented" — now partially resolved**: oauth.v2.access documents "The rate limit for this method is 600 per minute" (tier t5, "Special rate limits apply"); the authorize endpoint still has no published limit — https://docs.slack.dev/reference/methods/oauth.v2.access and https://docs.slack.dev/apis/web-api/rate-limits. Fixed blockers.
- **Draft's "unverified" list shrank**: Marketplace review SLA, re-review triggers (approved listing is locked; "resubmit after substantial changes or updates"), appeal process (official docs describe return-and-resubmit, not appeals), and Enterprise Grid org-wide approval flow are all now answered by official pages — https://docs.slack.dev/slack-marketplace/slack-marketplace-review-guide, https://docs.slack.dev/slack-marketplace/slack-marketplace-app-guidelines-and-requirements, https://docs.slack.dev/enterprise/developing-for-enterprise-orgs.

## Could not verify

- Rate limit for the `oauth/v2/authorize` endpoint (no published limit found; only oauth.v2.access documents 600/min).
- Classic Slack app (V1 OAuth) deprecation schedule.
- Whether the Client Secret is displayed only once at creation (no official statement either way; corrected step 4 no longer relies on the "shown once" claim).
- "Accept Slack API Terms of Service" as a step in *basic* app creation — the ToS agreement is only documented as part of Marketplace distribution ("By distributing through the Marketplace you agree to… API Terms of Service"); left unchanged in agent_vs_human as plausible but unverified for plain creation.
- Composio claim in `composio_next.managed_note` that "Slack is not in the Composio catalog; no managed OAuth available" — outside official Slack documentation; verify against Composio directly. Left unchanged.
- Exact console button labels beyond what official docs describe (the console at api.slack.com/apps is a signed-in JS app; wording taken from official docs, e.g. "Create an app" vs the draft's "Create New App").
