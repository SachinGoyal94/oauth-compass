# Linear OAuth App Setup Guide

Linear provides self-service OAuth app registration with instant creation for private apps. No external review is required for private apps; public apps are installable by other workspaces but no formal review process is documented. The flow uses standard OAuth 2.0 with PKCE support, 24-hour access tokens, indefinite refresh tokens (30-min replay grace), and optional client credentials grant (30-day tokens). Admins create apps via a direct URL or pre-populated manifest (JSON or URL params).

## Difficulty & time

Straightforward self-service registration; only admin role and manifest preparation required. No approval wait for private apps.

- **Difficulty:** Light (2/5)
- **Hands-on setup:** 10-15 minutes
- **Approval wait:** None

## Prerequisites

- **Required:** Linear workspace with admin role — Only workspace admins see Administration → API and can create OAuth apps. Create a dedicated workspace if needed.
- **Required:** Redirect URI(s) (1-32 unique absolute HTTPS URLs) — HTTP allowed only for localhost. Must match exactly at authorization time. Composio requires https://backend.composio.dev/api/v3/toolkits/auth/callback
- Optional: Scopes selection — Comma-separated; 'read' is always present. Choose from: read, write, issues:create, comments:create, timeSchedule:write, admin, app:assignable, app:mentionable.
- **Required:** Client name (2-80 chars, no 'Linear' or 'http(s)://') — Required for manifest; displayed to users during consent.
- **Required:** Client URI (absolute HTTP/HTTPS URL) — Homepage or docs URL for the application.
- **Required:** Developer name (2-80 chars) — Required for complete setup; shown in app details.
- Optional: Grant types — authorization_code required; client_credentials optional (must be toggled on in app settings after creation).

## Gotchas

- **Redirect URI exact match required** — Linear requires exact string match for redirect URIs; any mismatch (trailing slash, case, query params) causes authorization failure.
  - Handle: Register the exact URI used in the authorization request. Max 32 URIs per app.
- **Client secret rotation behavior** — Rotating client_secret immediately invalidates all client_credentials tokens but does NOT revoke user access/refresh tokens (they pick up new secret on next refresh).
  - Handle: Plan rotation carefully; expect brief outage for server-to-server tokens. User tokens self-heal on refresh.
- **Client credentials must be toggled on in settings** — Even if grant_types includes client_credentials in manifest, the grant will not work until enabled in the app's settings page after creation.
  - Handle: After saving the app, open its settings and explicitly enable the client_credentials toggle.
- **Scope immutability on existing tokens** — Changing scopes in the app config does not affect already-issued tokens; new scopes only apply to new authorizations.
  - Handle: Request all needed scopes upfront. Users must re-authorize to gain additional scopes.
- **Webhook URL restrictions** — Webhook URLs must be HTTPS; loopback, private-network, and linear.app hosts are rejected.
  - Handle: Use a public HTTPS endpoint for webhooks. Avoid localhost or internal IPs.
- **Actor=app tokens access all public teams** — Tokens obtained with actor=app have access to all public teams in the workspace; team access is adjustable post-creation but starts broad.
  - Handle: Use actor=app only for trusted service accounts. Adjust team access in Linear after app installation if needed.

## Common blockers

- **No admin role in workspace** — Request admin promotion from workspace owner or create a new workspace where you are admin.
  - Escalation: Workspace owner only
- **Redirect URI validation fails** — Ensure URI is absolute HTTPS, matches exactly (including trailing slash), and is not a disallowed host (loopback, private, linear.app).
  - Escalation: Linear support if validation appears incorrect
- **Client secret lost after creation** — Rotate client secret in app settings (invalidates client_credentials tokens immediately).
  - Escalation: Linear support
