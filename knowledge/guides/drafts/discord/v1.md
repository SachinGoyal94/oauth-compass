# Discord OAuth Setup Guide

Create and configure a Discord OAuth2 application in the Discord Developer Portal. Covers app registration, redirect URI configuration, scope selection, and the two review processes (App Verification for scaling past 100 servers and Privileged Intent Review for gateway intents).

## Difficulty & time

Straightforward console form-filling; main complexity is understanding the two separate review processes and scope approval requirements.

- **Difficulty:** Light (2/5)
- **Hands-on setup:** 15-30 minutes
- **Approval wait:** App Verification: no official timeline documented (community reports ~5 business days). Privileged Intent Review: 90-day window to apply after notification, no fixed SLA. Restricted scopes: no documented timeline.

## Prerequisites

- **Required:** Discord user account — Required to log into the Developer Portal.
- **Required:** Developer team (for verification) — App must belong to a developer team (not a personal account) to apply for App Verification. Team owner must complete identity verification via Stripe.
- **Required:** HTTPS redirect URI for production — Production redirect URIs must use HTTPS; HTTP is not permitted. Must be registered exactly (including trailing slashes) in the Developer Portal before use.
- Optional: Privacy Policy and Terms of Service URLs (recommended) — Available in Application Resource; recommended for public apps and required for Discovery listing.

## Step-by-step

### 1. Log in to Discord Developer Portal (https://discord.com/developers/applications)
Sign in with your Discord user account.
*[~1 minute, human step; evidence: verified_from_docs]*
> Use the account that will own the application or a team account if planning verification.

### 2. Create a new application (Discord Developer Portal → Applications page)
Click "New Application", enter a name, and confirm.
*[~1 minute, human step; evidence: verified_from_docs]*
> Name can be changed later. After creation you land on the General Information page.

### 3. Configure OAuth2 redirect URIs (Application → OAuth2 → Redirects)
Add the redirect URI(s) exactly as they will be used (including trailing slashes). For Composio, register https://backend.composio.dev/api/v3/toolkits/auth/callback
*[~2 minutes, human step; evidence: verified_from_docs]*
> Must match exactly in authorization request and token exchange. Production requires HTTPS. Mobile/desktop deep linking uses format `discord-YOUR_APP_ID:/authorize/callback`.

### 4. Copy Client ID and generate Client Secret (Application → OAuth2 → General)
Copy the Client ID. Click "Reset Secret" to generate a new Client Secret and copy it immediately (shown only once).
*[~1 minute, human step; evidence: verified_from_docs]*
> Store the secret securely. If lost, you must reset it again.

### 5. Select OAuth2 scopes via URL Generator (Application → OAuth2 → URL Generator)
Choose integration types (Guild Install, User Install) and required scopes (e.g., identify, email, guilds, bot, applications.commands). Copy the generated authorization URL for testing.
*[~3 minutes, human step; evidence: verified_from_docs]*
> Scopes marked "Requires approval" (identify.premium, relationships.read, voice, dm_channels.read, rpc.*, applications.builds.upload) will error if requested without explicit Discord authorization. Bot-only install links (only `bot` scope) do not require a redirect URI.

### 6. (Optional) Configure Installation Contexts (Application → Installation)
Enable Guild Install and/or User Install contexts as needed for your app's distribution model.
*[~2 minutes, human step; evidence: verified_from_docs]*
> Determines where users can install the app (servers vs. user account).

### 7. (Optional) Enable Discovery for App Directory listing (Application → Discovery)
Complete the Discovery checklist (privacy policy, terms of service, description, icons, etc.) and submit for listing. Requires App Verification first.
*[~10-20 minutes, human step; evidence: verified_from_docs]*
> App appears in App Directory up to 24 hours after enabling Discovery. Only available after App Verification.

### 8. Apply for App Verification when reaching 100 servers (Application → App Verification)
Ensure app belongs to a developer team. Complete team owner identity verification via Stripe. Fill all checklist items (green status). Click "Verify App" to submit.
*[~15-30 minutes + review wait, human step; evidence: verified_from_docs]*
> No official guaranteed timeline documented. Community/legacy sources suggest ~5 business days. Free. Allows scaling past 100 servers, monetization, and Discovery.

### 9. Apply for Privileged Intent Review when exceeding 10,000 unique users (Developer Portal notification → Privileged Intent Review)
When notified (at 10,000 unique users), submit detailed use-case justification for each privileged intent (Guild Presences, Guild Members, Message Content) within 90 days. Reapply annually.
*[~30 minutes + review wait, human step; evidence: verified_from_docs]*
> Separate from App Verification. Apps continue functioning during review. No fixed SLA documented. Threshold changed June 10, 2026 from 100 servers to 10,000 unique users.

### 10. Request restricted scope approval if needed (Via Discord account representative or Developer Portal submission)
Contact Discord account representative or submit request for scopes like dm_channels.read, identify.premium, voice, rpc.*, relationships.read, applications.builds.upload.
*[~Variable, human step; evidence: verified_from_docs]*
> No documented timeline. These scopes cause errors if requested without explicit approval.

## Gotchas

- **Redirect URI exact match required** — Trailing slashes matter; mismatch causes authorization failure.
  - Handle: Register the exact URI (including trailing slash) in the Developer Portal and use the identical string in authorization requests and token exchange.
- **Refresh tokens are single-use (rotating)** — Each refresh returns a new refresh token; reusing an old one causes invalid_grant requiring full re-authorization.
  - Handle: Store only the latest refresh token returned from each token refresh call. Implement atomic update of stored refresh token.
- **Access token lifetime differs by client type** — Confidential/server-side clients get 7-day tokens; Public Clients (PKCE) get 1-hour tokens. Enabling Public Client mode changes token lifetime.
  - Handle: Disable Public Client mode for production backend apps. Use PKCE only for desktop/mobile apps without backend.
- **Unverified apps capped at 100 servers** — App cannot join more than 100 guilds until App Verification is approved.
  - Handle: Plan for verification early if expecting growth. Move app to a developer team and complete Stripe identity verification for team owner.
- **Privileged Intent threshold is 10,000 unique users (not servers)** — As of June 10, 2026, the threshold changed from 100 servers to 10,000 unique users across all servers.
  - Handle: Monitor unique user count. Prepare justifications for Guild Presences, Guild Members, and Message Content intents well before hitting threshold.
- **Restricted scopes require explicit Discord approval** — Scopes like dm_channels.read, identify.premium, voice, rpc.*, relationships.read, applications.builds.upload will error if used without approval.
  - Handle: Only request these scopes if you have a Discord account representative or have submitted approval request. Use standard scopes (identify, email, guilds, bot, applications.commands) for most apps.
- **State parameter not required but highly recommended** — Discord does not enforce state parameter, but omitting it leaves CSRF vulnerability.
  - Handle: Always generate and validate a cryptographically random state parameter in your OAuth flow.
- **Issuer validation required** — Every redirect includes iss=https://discord.com; failing to validate enables authorization server mix-up attacks.
  - Handle: Verify the iss parameter matches https://discord.com in your callback handler.

## Common blockers

- **App stuck at 100 servers limit** — Complete App Verification: move app to developer team, verify team owner identity via Stripe, fill all checklist items, submit verification.
  - Escalation: If verification delayed beyond expected timeframe, check Developer Portal for status or contact Discord Developer Support.
- **Privileged Intent review notification received** — Submit detailed use-case justification for each requested intent within 90-day window. Reapply annually.
  - Escalation: If review exceeds reasonable time, check Developer Portal for status updates.
- **Restricted scope request denied or no response** — Ensure you have a valid business need. Contact Discord account representative directly. Consider alternative scopes or architecture.
  - Escalation: Escalate through Discord Developer Support or account representative.
- **Invalid redirect URI error during authorization** — Verify exact match (including trailing slash) between registered URI in Developer Portal and the redirect_uri parameter sent in authorization request and token exchange.
  - Escalation: N/A - configuration fix.

## What the agent can do vs. you

**An agent can:** Research Discord OAuth2 documentation and scope requirements; Prepare scope list and redirect URI values; Draft verification checklist items and privileged intent justifications; Generate authorization URLs for testing; Create Composio auth config snippet; Monitor server/user counts for threshold alerts.
**You must:** Log in to Discord Developer Portal; Create application and configure OAuth2 settings in console; Generate and securely store Client Secret; Complete Stripe identity verification for team owner; Submit App Verification and Privileged Intent Review applications; Accept legal terms and provide Privacy Policy/ToS URLs; Communicate with Discord account representatives for restricted scopes.

## Connect it via Composio

Discord is a Composio-managed OAuth toolkit (composio_managed_oauth: true). Use the managed flow; you only need to provide client_id and client_secret from your Discord Developer Portal application.

When using Composio's managed OAuth, the redirect URI https://backend.composio.dev/api/v3/toolkits/auth/callback must be registered in your Discord Developer Portal OAuth2 Redirects. Composio handles token exchange, refresh rotation, and storage.
